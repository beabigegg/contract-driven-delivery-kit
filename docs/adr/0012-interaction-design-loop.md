# ADR 0012: Interaction-design loop — human-confirmed design intent as a provenance-reconciled gate

- Status: Proposed
- Date: 2026-07-09
- Deciders: maintainer (non-coding spec author) + AI delivery agent
- Relates to: ADR 0010 (acceptance oracle — tamper-evidence template reused here),
  ADR 0011 (`applicability: not-applicable` skip path), ADR 0007 (data-shape
  conformance / `openapi.json` projection the provenance join reuses),
  `cdd-kit gate`, `interaction-design.md` (new artifact),
  `.cdd/design-lock.json`, `hooks/pre-tool-use-design-write.sh`,
  `contracts/api/api-contract.md`, `contracts/data/data-shape-contract.md`
  (`## Invalid Data Behavior`), `.claude/skills/cdd-new/SKILL.md`

## Context

ADR 0010 closed the intent gap for **function**: the non-coding author supplies
business-language ground truth, it is hash-locked, and agents cannot write it.
There is **no equivalent for design**. In `.claude/skills/cdd-new/SKILL.md` the
Tier 2–3 order runs `frontend-engineer` (step 7) before `ui-ux-reviewer` (step 9)
and `visual-reviewer` (step 10): design enters the pipeline only as after-the-fact
review. `implementation-plan.md` never states what information a screen presents
or how a user operates it. So the AI decides the shape of every interface,
unreviewed at the only altitude the author can operate at.

Industry evidence (TechOrange 2026-07-08, citing Business Insider) names three
tells of AI-built interfaces: regression-to-the-mean aesthetics; polished visuals
where only the happy path works and inert elements *look* clickable; and skipped
or formulaic edge states (empty / error / skeleton / offline). This ADR governs
**only the two mechanically-checkable ones** — happy-path-only and skipped edge
states — and explicitly refuses to govern the first (aesthetics). The remedy the
article names is a shift from *aesthetic prompting* ("make it clean and modern")
to *decision prompting* ("this is the screen where the user is anxious about
their data — what must my copy accomplish?"). This ADR forces that shift by making
the design *derivation* a first-class, human-confirmed artifact.

**The oracle problem restated for design.** A checker can only enforce consistency
against an oracle; it cannot invent taste. There is no oracle for beauty, so the
human's design direction is the only admissible source. This ADR's job is to
*force that direction into human hands* — never to simulate it.

### Two design mistakes already made during this ADR's own design (recorded as evidence)

**Rejected proposal #1 — an "affordance honesty" static scanner** that would
hard-fail any element carrying `cursor:pointer` / hover shadow / hover scale
without a click handler. Wrong because a hover highlight on a non-clickable row is
legitimate "your cursor is here" feedback. The rule cannot see context, so it
produces false verdicts. **A rule that does not know the context reproduces the
exact disease it claims to cure — it is AI slop generated by the gate instead of
by the agent.**

**Rejected proposal #2 — "a search filter must have a reset/clear button".**
Wrong because whether that button should exist is *derived*, not decreed. After
filtering to an empty result the user asks "is there really no data, or did I
filter it out?" That question needs an exit — and there are **two substitutable**
exits, not an additive requirement: make the filter state *perceivable* (an active
"B plant ×" chip the user can see and dismiss), or provide a global *reset*. With
one or two visible chips a reset button is gratuitous noise; with six controls
hidden in a collapsed panel that persist across reload, the absent reset traps the
user. The generalizable principle: **perceptibility and reversibility are
interchangeable ways to close the same loop.** A control is a *conclusion* of the
derivation, never a premise.

Therefore the object of governance is not "does this element exist" but
**"where was this element derived from."**

### A half-built bridge this ADR connects

`contracts/data/data-shape-contract.md` `## Invalid Data Behavior` already has a
column literally named `error code / UI state`, alongside a fixed `condition`
vocabulary (`missing required column`, `wrong type`, `empty dataset`,
`over max row limit`, `unexpected enum`). Those rows have **never had a consumer**,
because nothing in the kit ever recorded which UI states exist. This ADR makes
`interaction-design.md` that consumer — states cite a row by its stable `condition`
key (`data-shape: <condition>`, §2); the free-text `error code / UI state` column
stays human-authored prose and is not itself the machine key, so no change to
`data-shape-contract.md` is required.

## Decision

Add a per-change, human-confirmed artifact — `specs/changes/<id>/interaction-design.md`
— produced by a read-only `interaction-designer` proposer, reconciled against the
API and data-shape contracts in a **convergence loop**, and locked against agent
tampering with a hash before implementation proceeds.

### 1. The derivation chain the artifact carries (business language; no color/type/spacing)

1. **Presented information + rationale** — each item is the answer to some user
   question.
2. **User intents, ordered by real frequency** (not feature importance), each with
   the path that serves it.
3. **Control ↔ intent mapping** — every control cites exactly one intent id.
   Controls *considered and deleted* are recorded WITH the reason (this is where
   proposal #2's reset button dies honorably). This is the kit's
   `Solution Minimalism (reuse-first)` ladder — "does this need to exist at all?"
   — applied to the interface; that ladder was previously scoped to solution CODE
   only, and layout elements had never been interrogated the same way.
4. **Reversibility** — after entering a state, can the user tell where they are and
   get back.
5. **Consistency commitment: a bijection between meaning and form.** Same meaning ⇒
   same form; different meaning ⇒ different form. This is the correct home for the
   hover/animation concern: what is forbidden is not motion, but *one visual form
   carrying two different meanings* (the "clickable card" vocabulary applied to an
   inert block). AI slop is bad not because it is ugly but because uniform visual
   weight destroys the form's capacity to *encode* information.
6. `## Open Decisions` — questions the agent puts to the human, each with options
   and trade-offs.
7. `## Confirmed` — the human's answers, timestamped, hash-locked (§4).

### 2. Provenance reconciliation (the join rules and the hard/advisory boundary)

Every information item and every UI state must name its supplier: an
`api-contract.md` endpoint + schema field, an `errors`-column HTTP status, an
implicit HTTP status, or a `data-shape-contract.md` `## Invalid Data Behavior` row.
(The `errors` column holds bare HTTP-status integers, never a semantic error code —
see "What the `errors` column actually holds" below.) Field existence is joined
mechanically against the ADR 0007 `openapi.json` projection.
The six ways a frontend writes a cheque the backend cannot honor:

| # | Blank cheque | Backend reality | Verdict |
|---|---|---|---|
| 1 | screen shows "unreported line count" | field in no response schema | **HARD** (field existence) |
| 2 | design distinguishes "nothing is wrong" from "no data received" | API returns `[]` for both — no discriminator | **HARD** (every state must name a discriminator) |
| 3 | permission error vs network error get different copy | backend returns 500 for both | **HARD** — resolves through one of two *existing* supplier kinds: (a) two **distinct HTTP statuses**, or (b) a **discriminator field pinned to an enum member** in a typed success envelope (the ADR 0010 `{status:"rejected", reason:"credit-limit-exceeded"}` pattern) |
| 4 | screen promises "data as of 09:12" | response carries no timestamp | **HARD** (same as #1) |
| 5 | `abandon-if: no feedback within 3s` | that query's p95 is 8s | **OUT OF SCOPE** — semantic, not statically joinable; latency belongs to `stress-soak-engineer` |
| 6 | "see all 10 lines at a glance" | API is one request per line (N+1) | **ADVISORY** — the table surfaces the fact; the judgment is human |

Failure mode #2 is the strongest justification for this whole ADR: **an empty array
is one value to the backend and two entirely different worlds to the user** —
"today is calm" (green) versus "the system is blind" (warning). An AI-written
frontend renders them identically 100% of the time, because no contract ever forced
anyone to answer "how do you tell these two apart?"

**What the `errors` column actually holds (and what it does not).** The
`api-contract.md` `errors` cell holds **bare, comma-separated HTTP-status integers
only** (e.g. `400, 409`); `openapi-export.ts` extracts them with `/\b[1-5]\d\d\b/g`
and carries no semantic error code. The kit's semantic error-code registry is a
*separate sibling contract*, `contracts/api/error-format.md` → `## Error Codes`
(`code | status | user-facing message | retryable | owner`); it is not
endpoint-scoped and is not projected into `openapi.json`. **`error-format.md` is
deliberately NOT a join target in this ADR** — see Out of scope. Row 3 therefore
resolves through a distinct HTTP status or an enum-pinned success-envelope field,
never through a semantic code.

**Citation syntax (mechanically parseable — implement exactly this, not a variant).**

| Supplier kind | Citation form |
|---|---|
| Endpoint + schema field | `<METHOD> <PATH> → <field>` (nested: `<field>.<nested>`; array-element fields cited by bare name — the resolver descends `items` transparently) |
| Enum discriminator pin | `<METHOD> <PATH> → <field>=<enum-member>` (also checks the member is in that field's `enum(...)` list; this is how meaning-distinct states cite *which value* of a shared field discriminates them) |
| `errors`-column status | `<METHOD> <PATH> → <status-code>` (must be a token in that row's `errors` cell) |
| Implicit HTTP status | `<METHOD> <PATH> → HTTP <code>` (the method-derived success code: `201` for POST, else `200`) |
| Invalid-data row | `data-shape: <condition>` (verbatim `condition` column value) |

Resolution for the first two goes through the endpoint row's **bare** `response
schema` cell (bare-name requirement already enforced by the ADR 0007 near-miss
rule) → `components.schemas` in `openapi.json` → dotted path walk.

**Degradation rules (stated here, not left to the implementer).**

- **Field-existence resolution** reuses the ADR 0007 `contracts/api/openapi.json`
  projection and does not re-derive it. If the projection is missing or stale
  (`openapi export --check` would fail), OR the cited endpoint's `response schema`
  cell is unresolved prose with no matching `## Schemas` entry, then any
  endpoint+field citation is a **HARD failure with an actionable message** — never a
  silent skip. `enforceInteractionDesign` is a required blocking gate; a citation
  asserting a field exists is a positive claim, and an unverifiable positive claim
  must not pass. (This differs deliberately from ADR 0007's own response-shape
  validator, which is opt-in and quietly skips untyped endpoints.)
- Citations of a **bare HTTP status** or an **`errors`-column status** do NOT require
  the projection and stay checkable when `## Schemas` is empty.
- If `api-contract.md` or `data-shape-contract.md` itself carries
  `applicability: not-applicable`, citing that family's supplier kinds is its **own
  HARD failure category** with a marker-aware message (naming the marker and its
  reason), distinct from "reference not found": citing a family the project declared
  it does not have is a different, more actionable error.
- `## Invalid Data Behavior` rows are keyed by the **`condition` column**
  (`missing required column`, `wrong type`, `empty dataset`, `over max row limit`,
  `unexpected enum`) — a fixed, non-repeating vocabulary that already functions as a
  stable key. The free-text `error code / UI state` column is NOT the citation
  target. **No change to `data-shape-contract.md` is needed** — recorded here so a
  later implementer does not "fix" it.

**State-discriminator strictness — decided HARD at introduction.** Two UI states
that differ in meaning MUST cite *distinct* discriminators (distinct HTTP statuses,
or distinct enum-pinned values of a shared success-envelope field); a state that
cites a discriminator absent from the contract is a HARD error that drives the
back-edge (§3) — the backend must add the discriminator (a field, a distinct HTTP
status, a timestamp) before either side freezes. This keeps AC-5 in
`change-classification.md` as written; it is not downgraded to advisory.

**Reverse direction is ADVISORY only, and is NOT computed by the per-change gate.**
A contract field with zero consuming information items = possible over-fetch. But a
per-change `interaction-design.md` cannot see sibling screens, and
`.cdd/context-policy.json` forbids agents reading sibling `specs/changes/*`;
computing "zero consumers" over one change's artifact would flag every field not
used by that one screen — a firehose of false advisories, precisely the
context-blind failure the Never Gated section condemns. So the reverse direction is
a **corpus-wide `cdd-kit doctor` report** that scans all
`specs/changes/*/interaction-design.md` repo-wide (a CLI validator, not an agent
read, so it is not bound by any single change's context-manifest). Advisory-only,
never gate-blocking — precedent: the ADR 0007 response-shape adoption-coverage
report.

### 3. Convergence loop, not a straight line (node placement + back-edge)

`interaction-designer` runs **after `contract-reviewer`** (the contract bounds what
data can appear) but **before `implementation-planner`**. It is NOT downstream-only:
the design also *demands* new things from the backend (discriminators, timestamps,
distinct error codes — the HARD rows above). Contract and design are **mutually
constraining**. When reconciliation finds an unresolvable HARD reference,
`interaction-designer` emits the demand and control loops **back to
`contract-reviewer`** to update the contract, then re-runs — until provenance
reconciliation converges (zero unresolvable references). Only then are **both** the
contract and `interaction-design.md` frozen. This corrects the original proposal's
ordering error (placing the designer strictly after the contract-reviewer was "only
half true and therefore wrong").

Downstream role changes:
- `frontend-engineer` reports `blocked` when the design is unconfirmed; the states
  line loses its `when applicable` escape hatch — every state comes from the
  confirmed design, never AI's own judgment.
- `implementation-planner` references the confirmed design by path/section.
- `ui-ux-reviewer` reviews **against the confirmed design** (Nielsen-style generic
  heuristics demoted to a secondary lens) and its broken `contracts/ui/` pointer is
  corrected to `contracts/css/`.

### 4. Human-in-the-loop despite no subagent↔user channel

Subagents cannot converse with the user. So the dialogue is choreographed exactly
like the kit's two existing precedents in `.claude/skills/cdd-new/SKILL.md` —
`## Step 0: Request quality check` and `## Atomic Split Proposal`:
`interaction-designer` **proposes** (fills the chain + `## Open Decisions`) →
**main Claude runs the dialogue** with the human → **human decides** → **main Claude
writes** the answers into `## Confirmed` → `cdd-kit design confirm <id>` **locks**.
The agent never authors `## Confirmed`; the human's answers are the only admissible
source, transcribed but not invented (ADR 0010 §2 discipline).

### 5. Tamper-evidence (reused verbatim in spirit from ADR 0010 §3)

- **Hash-lock over a canonical parsed projection.** `cdd-kit design confirm` records
  a sha256 of the *semantic projection* of the confirmed chain (parsed structure,
  not raw bytes — reformatting must not break the lock) in `.cdd/design-lock.json`.
  A later agent edit diverges the hash and fails gate with "interaction design
  modified after confirmation — human must re-confirm."
- **Single sanctioned writer.** `cdd-kit design confirm <id>` is the ONLY path that
  writes `.cdd/design-lock.json`.
- **Hook installation is not assumed — it is checked.** An unregistered hook blocks
  nothing. This ADR previously asserted, present-tense, that
  `pre-tool-use-design-write.sh` "blocks agent Edit/Write to `.cdd/design-lock.json`".
  It did not: the hook was never registered in this repository, and
  `installAgentHooks` arms a write-block hook only on an explicit opt.
  `cdd-kit gate`'s `enforceConfirmationHookInstallation` now warns (default) and
  hard-fails (`--strict`) when the design/acceptance write-block hooks are absent
  from the project `.claude/settings.json`. It verifies only that file, never the
  harness's effective merged settings.
- **Agent write-block hook — path-keyed, not a global toggle.**
  `CDD_DESIGN_WRITE_STRICT` / `CDD_ACCEPTANCE_WRITE_STRICT` are retired. The hook
  payload carries no agent identity, so a global switch could only block everyone —
  including main Claude's sanctioned transcription — or block nobody, its default.
  The hooks now discriminate on the write target path: an Edit/Write/MultiEdit of
  `.cdd/design-lock.json` / `.cdd/acceptance-lock.json` is blocked unconditionally;
  the artifact body stays writable, so the sanctioned first write and the human-answer
  transcription still go through.
- **Tamper evidence, not prevention.** The locks record git-author, TTY, and
  timestamp provenance at confirm time, auditable by a human. A determined
  `Bash`-holding agent can still reach the lock (`cdd-kit design confirm`,
  `node dist/cli/index.js`, a shell redirect, or `node -e` into the lock writer): its
  shell shares the human's filesystem and user account. The hook is a speed bump plus
  evidence, not a prevention boundary. Prevention-grade closure needs a signature only
  the human's environment can produce — a hardware key, or the lock committed under
  the human's authenticated remote git identity. Deferred; not claimed here. This
  bullet exists so the guarantee is never again announced stronger than it holds.
- **Non-vacuous derivation chain.** Under `isNewChange || strict`,
  `enforceInteractionDesign` fails a confirmed design whose `## Presented Information`
  or `## States` table has zero rows. Provenance reconciliation over an empty set
  passes trivially, so without this a human could confirm a document asserting
  nothing. `applicability: not-applicable` remains the single sanctioned escape and
  short-circuits ahead of the row count.
- **Migration window.** The new gate check uses `isNewChange || strict` (as
  `enforceAcceptanceOracle` / `enforceTestEvidence` do) so legacy change dirs do
  not all fail overnight.

### 6. Gate check `enforceInteractionDesign`

Registered as a REQUIRED check in `contracts/ci/ci-gate-contract.md`. Fails when:
`interaction-design.md` is missing; any `## Open Decisions` is unresolved; no human
`## Confirmed`; referential integrity breaks (every control cites one intent id;
every intent has one path); provenance reconciliation has any HARD failure; or the
confirmed-region hash mismatches (§5). The N+1 advisory (row 6) is surfaced but
never blocks. The reverse/over-fetch advisory is **not a gate finding at all** — it
is a corpus-wide `cdd-kit doctor` report (§2), because it is only meaningful across
all changes' interaction designs and cannot be computed inside one change's context.

### 7. Sanctioned skip (reused from ADR 0011)

A pure copy/color tweak may skip this node via `applicability: not-applicable` with
a mandatory non-empty `applicability-reason`. `applicability.py` stays the single
pass/fail authority — no second TypeScript authority is added.

### 8. Portable-layer rule (ADR 0010 §5)

Every guarantee here lives in the portable layer — CLI validators and `cdd-kit gate`
— so it holds for Claude Code, Codex, and headless CI. The settings.json write-block
hooks are the one thing that is **opt-in and unverified by any harness other than
this gate**: `enforceConfirmationHookInstallation` confirms the project's
`.claude/settings.json` arms them, but cannot confirm that the harness actually
running an agent honours that registration, and cannot stop a `Bash`-holding agent
from bypassing an installed hook. The durable guarantee is the mechanical gate check
— hash-lock, provenance, hook-presence. The hook is evidence and a speed bump layered
on top, not itself the guarantee. This paragraph previously said the hooks were part
of the portable guarantee without stating that they were opt-in, defaulted off, and
checked by nothing; that omission is exactly how the write-block came to be shipped,
documented, and never once installed. Claude Code's Workflow / Loop / Worktree may
*automate* the propose→confirm choreography but never *guarantee* it.

## Never Gated (a written prohibition binding on all future contributors)

The following are NEVER mechanically gated. A rule over any of them would misjudge,
because none has an oracle a checker can consult:

- **Visual aesthetics** (color, "beige/rounded/drop-shadow"): there is no oracle for
  beauty; the human's direction is the only admissible source. This is the same
  reason the acceptance oracle exists.
- **Animation and motion**: motion is not the disease (§1.5). Rejected proposal #1
  shows a motion/affordance rule producing false verdicts.
- **Layout taste and information density**: context-dependent; "does this element
  exist" is the wrong question (rejected proposal #2).
- **Typography and color choices**: no oracle; direction only.
- **Latency and round-trip count (N+1)**: semantic, not statically joinable; belongs
  to `stress-soak-engineer` (table row 5, and row 6 is advisory-only).

The principle, stated plainly: **mechanical checks may only enforce consistency
against an oracle; they may never originate taste.** Rejected proposals #1 and #2
are the recorded evidence that this failure already happened during this ADR's own
design — they are why this section exists.

## Consequences

- The design intent gap closes at the one point only a human can close it: the
  author confirms what each screen presents, why each control exists, and how each
  state is told apart — and the kit enforces provenance and tamper-evidence around
  that confirmation.
- Failure mode #2 (empty-array-means-two-worlds) becomes impossible to ship
  silently: every state must name a discriminator the contract actually supplies.
- The convergence loop stops the frontend writing cheques the backend cannot honor,
  *and* stops the contract from silently under-supplying — the demands flow both
  ways before either freezes.
- The dormant `error code / UI state` column in the data-shape contract gains its
  first consumer.
- Residual cost, honestly stated: the human must actually answer the `## Open
  Decisions`. A lazy-but-well-formed confirmation buys nothing; no mechanism detects
  it. This is the irreducible oracle role, as in ADR 0010.

## Rejected alternatives

- **Just make `ui-ux-reviewer` stricter.** Rejected: AI reviewing AI adds zero
  information (the ADR 0010 rubber-stamp argument). Review is not authoring; it
  cannot supply the missing human direction.
- **Generate the design from the API contract automatically.** Rejected: that is
  exactly the regression-to-the-mean machine — it manufactures the average
  interface the ADR exists to prevent, with no human intent injected.
- **An "affordance honesty" scanner (proposal #1)** and **a "filter needs reset"
  rule (proposal #2)** — rejected; see Context. They are the concrete disease.

## Out of scope / future work

- A long-lived "layout language" contract under `contracts/css/` (cross-change,
  durable design vocabulary) is DEFERRED to a future ADR. `interaction-design.md`
  is per-change only for now.
- No CSS/token/color scanner (Never Gated).
- Latency-budget / N+1 verification stays with `stress-soak-engineer`.
- Request-body provenance (symmetric to response-body) deferred, mirroring ADR 0007.
- **Semantic error-code joins deferred.** A non-2xx JSON error body carrying a
  semantic code (e.g. `403 {"error_code": "PERMISSION_DENIED"}`) has no typed-schema
  mechanism today: `## Schemas` / Tier A / Tier B and the `openapi.json` projection
  resolve the **success** response only (ADR 0007's own scope). Joining a semantic
  code would require declaring `contracts/api/error-format.md` a fifth join target
  and extending the OpenAPI export to type error responses. That is a real gap
  **not created by this change**, and is deferred; row 3 above resolves through
  distinct HTTP statuses or enum-pinned success fields instead. This ADR does not
  expand scope to close it.
