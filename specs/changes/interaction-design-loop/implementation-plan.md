# Implementation Plan: interaction-design-loop

## Objective

Ship the design-side counterpart to the ADR 0010 acceptance oracle: a per-change,
human-confirmed `interaction-design.md`, produced by a read-only
`interaction-designer` proposer, reconciled against the API and data-shape contracts
(provenance), hash-locked against agent tampering, and enforced by a new REQUIRED
gate check `enforceInteractionDesign` — plus make `cdd-kit gate` actually run in CI.
All mechanism decisions are already locked in `docs/adr/0012-interaction-design-loop.md`;
this plan is the execution packet for `backend-engineer`. Owner for every block below
is `backend-engineer` (TypeScript CLI/validators/gate/schema/hook + `.claude/` prompt
edits + `node build.js`).

## Constraints and Risks

- **TOP RISK — `isNewChange` threading (ci-gates.md § Migration Window).**
  `enforceInteractionDesign` MUST accept `isNewChange` as a threaded parameter with the
  SAME signature shape as `enforceAcceptanceOracle`:
  `(cwd, changeDir, changeId, isNewChange, strict, errors, warnings)`. `isNewChange` is
  computed ONCE at `gate.ts:93` via `isContextGovernedChange(changeDir)`
  (`gate-artifacts.ts` — reads `tasks.yml` frontmatter `context-governance: v1`, NOT
  directory age or file presence). Do NOT re-derive a local new-vs-legacy signal (e.g.
  `!existsSync(interactionDesignPath)`): that silently decouples the migration window from
  the canonical definition and turns this additive minor bump (0.3.0→0.4.0) into an
  overnight breaking failure for every legacy change dir — the exact outcome the shared
  threading exists to prevent.
- **Hash projection must be semantic, not byte-level (ADR 0012 §5; design.md Open Risks).**
  A raw-file digest re-introduces false-tamper failures on reformat. Mirror
  `acceptance-hash.ts`'s parsed-projection approach exactly.
- **Provenance resolver is the highest-risk new unit surface (test-plan.md Notes).** Its
  degrade-path messages ARE the actionable-error contract (ADR 0012 §2), not just
  pass/fail. A false-positive HARD failure is a P0 resolver bug fix, never grounds to
  demote the check to informational. Reuse the ADR 0007 projection; do not re-derive it.
- **Provenance coverage is only as deep as the API contract is typed (design.md Open
  Risks; ADR 0012 degradation rules).** Untyped endpoints → endpoint+field citation is a
  HARD failure with an actionable message, never a silent skip (this differs from ADR
  0007's opt-in response-shape validator, which quietly skips). Bare HTTP-status / errors-column
  citations stay checkable when `## Schemas` is empty.
- **`.cdd/code-map.yml` staleness** would weaken any SUT/graph reasoning; refresh with
  `cdd-kit code-map` before deep work. If the map is missing/stale during planning, note
  it — the file/line pointers in this plan (gate.ts:93/180, init.ts:298-316,
  context.ts:39, new-change.ts:75-91, cli/index.ts:19/570) were read directly from source
  this session and are current as of 2026-07-09.
- **Dogfooding is blocking (IP-12).** Without this change's own
  `interaction-design.md` (`applicability: not-applicable` + reason), the change fails the
  very gate it ships (contract-reviewer + ci-cd-gatekeeper both flagged this).
- **Verbatim-text dependency.** The ci-gate-contract §1a–1g text is not in the change
  directory; it is held by the coordinator. If not supplied at implementation time, report
  `blocked` on IP-9 rather than authoring a substitute.
- A lazy-but-well-formed `## Confirmed` is undetectable (irreducible oracle residual, ADR
  0010/0012): the gate proves consistency against the human's answer, not that the human
  thought hard. This is by design, not a defect to "fix" with more rules.
