# Design: acceptance-oracle

## Summary
Implements ADR 0010: a human-owned `acceptance.yml` per change plus an
`enforceAcceptanceOracle` gate check that requires the implementation to pass the
author's `input→expect` cases against the real SUT, with the answer key locked
against agent tampering by four layers (hash-lock, write-block hook, mock-of-SUT
scan, executed evidence). This design resolves the three open questions ADR 0010
left — canonical hash serialization + baseline storage, per-stack driver-loader
emission, and digest-stamp storage — and records the portable-enforcement vs
harness-automation boundary as a binding constraint. No new architectural
boundary is introduced beyond ADR 0010; each mechanism mirrors an existing kit
pattern (metadata reconciliation, ADR 0005 evidence, ADR 0004 §6 chokepoint hook,
`src/utils/digest.ts`).

## Key Decisions

- **Q1 canonical hash — hash a parsed+canonicalized projection, not file bytes.**
  Parse `acceptance.yml`, project the locked region, recursively sort object keys,
  sort `cases` and `rules` by `id`, serialize as canonical JSON, run
  `normalizeContentForHash`, then sha256. Hashing the parsed projection (not raw
  bytes) is inherently key-order/whitespace/quoting/line-ending independent —
  which is why it is preferred over hashing the file the way `sha256OfFileNormalized`
  does (that would trip on cosmetic reformatting). → rejected raw-file digest:
  reformatting a semantically identical file would false-alarm.
- **Q1 locked fields — lock `cases[].{id,input,expect}` and `rules[].{id,statement}`;
  exclude `given/when/then`, `oracle-version`, `authored-by`.** `input/expect` is
  the answer key; `id` is the join key binding a case to its driver + evidence, so
  a rename must trip re-confirm. `given/when/then` is human narrative the author may
  reword without changing the oracle → locking it would produce false tamper alarms
  and discourage clarifying prose.
- **Q1 baseline storage — `.cdd/acceptance-lock.json` sidecar keyed by change-id,
  not `change.yml` and not `tasks.yml`.** The gate compares the freshly computed
  hash to an author-time baseline. `change.yml` is fully derived and regenerated by
  `cdd-kit metadata` from the very file it would guard, so a baseline there is
  trivially re-stampable and conflates freshness with tamper-evidence → rejected.
  `tasks.yml` is routinely agent-written (status), the weakest place for an
  anti-agent baseline → rejected. The sidecar is added to `.cdd/context-policy.json`
  forbidden paths and the acceptance-write hook's path match, giving it the same
  protection class as `acceptance.yml`. This refines ADR 0010 §3.1's "change
  metadata" wording; no new ADR — it stays within ADR 0010's accepted boundary.
- **Q2 driver loader — cdd-kit EMITS a per-stack loader (Python/pytest first),
  not a convention.** A "please read expect from the file" convention is
  unenforceable, which defeats the point. The kit emits a read-only loader/fixture
  that parses the change's `acceptance.yml` and exposes `id→{input,expect}`; the
  agent-authored driver imports it and asserts `SUT(input) == expect`. Mechanically
  checkable by the gate two ways: (a) each driver must reference the emitted loader
  symbol; (b) the gate scans each driver for a literal occurrence of any case's
  `expect` value — a hardcoded answer key fails ("driver hardcodes the answer key;
  read it from acceptance.yml"). Same bounded text/AST-scan family as the mock-of-SUT
  scan; ties to AC-4/AC-5. → rejected convention-only: no mechanical hook.
- **Q3 digest stamp — single `.cdd/asset-manifest.json` sidecar, not per-asset
  frontmatter.** Frontmatter cannot be added to `.sh` hooks or `settings.json`
  without breaking or altering them, and stamping into an asset changes that asset's
  own digest (self-referential; forces a fragile exclude-the-stamp region). A sidecar
  records `{relpath: {version, digest}}` for each installed asset without touching
  content — directly satisfying ADR 0010 §6's "don't mutate content in a way that
  changes the digest." → rejected per-asset frontmatter: breaks non-frontmatter
  assets and is self-referential. `refresh`/`upgrade`/`install-agent-hooks` write the
  manifest after each copy (reusing `sha256OfFileNormalized`); `doctor` recomputes
  installed digests and compares to the manifest (post-install drift) and to the
  packaged asset (stale/partial install), satisfying AC-8.

- **Binding constraint (ADR 0010 §5) — portable enforcement, harness automation.**
  Every guarantee (the four tamper layers + the gate) lives only in CLI validators /
  `gate` / `settings.json` hooks, so it holds for Claude, Codex, and headless CI. A
  change never passes because a harness feature ran. Workflow/Loop/Worktree only
  automate the same CLI. The write-block hook is the one legitimate harness
  dependency (written to `settings.json`, itself gate/doctor-detectable). Planner and
  backend-engineer MUST make every AC satisfiable by `cdd-kit gate` + hooks alone,
  verifiable with no Claude harness present.

## Migration / Rollback
`acceptance.yml` joins the change template set: `refresh`/`upgrade` add it for new
work; `migrate` scaffolds a placeholder-plus-instructions file into existing
in-flight change dirs (same path that upgrades `tasks.yml`/`agent-log`). A migrated
change intentionally FAILS `enforceAcceptanceOracle` until the author supplies real,
non-placeholder cases (reusing existing `meaningfulChars`/placeholder detection) —
the oracle is never silently skipped. Non-behavioral (pure-refactor) opt-out is
strictly harder than ADR 0005's: reference-parity or an agent-forbidden,
review-countersigned `acceptance-not-applicable` reason only. Rollback: the gate
check is additive; reverting removes the check, template, hook, and stamping with no
data migration. The `.cdd/asset-manifest.json` and `.cdd/acceptance-lock.json`
sidecars are regenerable and safe to delete.

## Maintainer Decisions (director rulings, 2026-07-08)
These resolve the two flagged risks below and are binding on planner + backend:
- **Lock sidecar is a HARD forbidden path from day one.** `.cdd/acceptance-lock.json`
  is agent-write-forbidden in `.cdd/context-policy.json` from the first release (not
  advisory). An agent may never write or re-stamp it; a legitimate human oracle change
  re-stamps the baseline only via an explicit human-run command (e.g. `cdd-kit accept
  relock`), never as an agent side effect. This closes the "baseline co-update
  residual" in isolation, not only via layered defense.
- **Both stacks now: Python AND JS/TS driver-loader + scans ship together.** Not
  Python-first. Rationale: cdd-kit itself is TypeScript/vitest, so full self-dogfooding
  of the driver `expect`-read + mock-of-SUT scans requires the JS/TS loader in the same
  change. AC-4/AC-5 mechanical coverage therefore spans Python (pytest) and JS/TS
  (vitest) at release. This widens scope ~1.5–2× vs Python-first; accepted.

## Open Risks
- **Maintainer decision — baseline co-update residual.** If the write-block hook is
  off/bypassed, an agent that edits `acceptance.yml` could also re-stamp
  `.cdd/acceptance-lock.json`, defeating hash-lock in isolation. Layered defense
  (write-block + `authored-by` provenance + mock-scan + executed evidence) holds, but
  the maintainer should confirm the sidecar-baseline model over embedding the hash in
  a human-signed field, and whether the lock sidecar should be a hard forbidden path
  from day one.
- **Scope narrowing (confirm).** Driver-loader emission is Python/pytest-first;
  JS/TS is a documented follow-up. This narrows AC-4/AC-5 mechanical coverage to
  Python stacks initially — matches the user's Conda/pytest default and ADR 0005's
  pytest-first precedent, but should be an explicit maintainer call.
- **Irreducible residual (ADR 0010).** No mechanism detects a lazy-but-well-formed
  oracle; the gate can only require ≥1 non-placeholder case and nudge coverage. This
  is the author's oracle role and cannot be delegated.
- **Mock-of-SUT precision.** SUT resolution depends on code-map accuracy
  (name-based cross-file resolution is the known weak spot); over-strict scanning
  could false-positive on legitimate external-boundary fakes (network/clock). Start
  conservative, mirroring ADR 0004 §5's minimal-then-grow rule set.
