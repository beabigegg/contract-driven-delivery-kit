## Approved Expansions

- request-id: CER-001
  requested_paths:
    - src/commands/gate.ts
    - src/commands/gate-shared.ts
  reason: The classifier could not tell from the indexes where `enforceInteractionDesign`
    is dispatched from. Main Claude resolved it before any agent ran:
    `src/commands/gate.ts:181` and `:184` are the sole call sites, and they compute
    the `isNewChange || strict` migration window that AC-1 and AC-7 both depend on.
    `gate-shared.ts` exists and is on the same path.
  status: approved
  approved-by: main Claude (pre-verified; both files confirmed to exist)

- request-id: CER-002
  requested_paths:
    - test/cli/gate.test.ts
  reason: End-to-end gate coverage for the combined design + acceptance flow is
    asserted at the top-level gate test rather than the per-command tests.
  status: approved
  approved-by: main Claude (file confirmed to exist)

- request-id: CER-003
  requested_paths:
    - src/utils/logger.ts
  reason: AC-2 and AC-4 require stream-level assertions (`log.warn` → stdout,
    `log.error` → stderr). test-strategist and backend-engineer must read the
    logger to know which stream a given severity lands on; the exit code is not a
    discriminator in gate tests.
  status: approved
  approved-by: main Claude

- request-id: CER-004
  requested_paths:
    - src/utils/markdown-section.ts
  reason: `parsePresentedInformation` / `parseStates` are LOCAL functions in
    `gate-design.ts:178,187` (not exports of `design-provenance.ts`, as main Claude
    first assumed and spec-architect corrected). They call `sectionBody`, which
    lives here. AC-1's row check reuses the `infoItems` / `states` arrays already
    computed at `gate-design.ts:340-341`.
  status: approved
  approved-by: main Claude (verified: the two functions and their call sites exist)

- request-id: CER-006
  requested_paths:
    - src/utils/markdown-section.ts
    - src/commands/design.ts
    - src/utils/design-provenance.ts
    - src/commands/gate-design.ts
  agent: contract-reviewer
  reason: contract-reviewer twice specified a section boundary ("to the next heading of
    equal-or-shallower level") that `sectionBody` does not implement, and mis-counted an
    anchor's occurrences, because it could not read the function it was legislating over.
    Both errors were about code outside its packet. It also cannot quote `design confirm`'s
    literal stdout strings without `design.ts`. Granting the reads is cheaper and more
    accurate than main Claude measuring on its behalf each round.
  status: approved
  approved-by: main Claude

- request-id: CER-005
  requested_paths:
    - .claude/settings.json
    - .claude/hooks/
  reason: The live PreToolUse registration is the evidence for the not-installed
    finding (only `graph-first` and `test-runner` are armed; the three write-block
    hooks are absent). Fork option (g) turns hook installation into a checked
    condition, so implementers and reviewers must be able to read the resolved
    project settings and the installed hook scripts.
  status: approved
  approved-by: main Claude
