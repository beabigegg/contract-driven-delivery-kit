# API and data-boundary doctrine

- CDD-API-001: The canonical contract owns method, path, request, response, error, optionality, nullability, and enum semantics.
- CDD-API-002: Identify producers, runtime branches, and consumers before changing a visible field.
- CDD-API-003: Validate serialized boundary behavior; internal model agreement alone is insufficient.
- CDD-API-004: Generated projections are disposable and must record their canonical input digest.
- CDD-API-005: Zero applicable typed checks for an API-affecting change is a failure.
